# TTS Distributed Cache — Workflow Reference

This document describes exactly how every cache lookup and write flows through
the system, what each layer does, and what happens under failure.

---

## Architecture Overview

```
Client (WebSocket)
        │
        ▼
   server.py  ─── handle_connection()
        │
        ▼
  CacheManager.get(key)
        │
   ┌────┴─────────────────────────────────────┐
   │             READ PATH (in order)         │
   │                                          │
   │  1.  L1 in-process LRU index             │
   │         (OrderedDict, no I/O)            │
   │  2.  Legacy flat-dir caches              │
   │         (cached_data_simran/, etc.)      │
   │  3.  L1 local SSD (sharded tree)         │
   │         ~/FlowTTS/distributed_cache/     │
   │  4.  L2 GCS                              │
   │         gs://kapturecx-ml/tts-cache/     │
   │  5.  DragonflyDB lock → wait or generate │
   └──────────────────────────────────────────┘
        │ miss
        ▼
   GPU synthesis  (sglang LLM + ncodec)
        │
        ▼
   WebSocket response sent to client  ◄── RESPONSE GOES OUT HERE
        │                                  (before cache write)
        ▼  (background thread)
   store_async()
        │
   ┌────┴──────────────────────┐
   │         WRITE PATH        │
   │  L1 local SSD  (atomic)  │
   │  L2 GCS        (PUT)     │
   │  DragonflyDB lock release │
   │  DragonflyDB metadata     │
   └───────────────────────────┘
```

## Cache Key

Before any lookup, a `CacheKey` is computed from the request parameters.

**File:** `flowtts/cache/cache_key.py`

```
SHA256(
  NFC_normalise(collapse_whitespace(text))
  \x00
  voice_id
  \x00
  model_version
  \x00
  speaking_rate (3 dp, e.g. "1.000")
  \x00
  language
  \x00
  sorted_json(extra_params)
)
```

Fields are separated by NUL bytes so no field value can bleed into an
adjacent field's contribution to the hash.

The resulting 64-character hex string is called the **digest**.  It drives:

| Key | Format | Purpose |
|-----|--------|---------|
| File path | `ab/cd/<digest>.wav` | Storage on disk and in GCS |
| Lock key | `lock:<digest>` | DragonflyDB distributed lock |
| Meta key | `audio:<digest>` | DragonflyDB hit counters / metadata |

**Why this matters:** changing `model_version` in config immediately
invalidates all prior cache entries for every voice — no stale audio from
old checkpoints is ever served.

## Read Path — Step by Step

### Step 1 — L1 in-process LRU index

**File:** `flowtts/cache/local_cache.py`

```
_l1.get(digest)   ─── O(1) OrderedDict lookup, zero I/O
```

- Stores digest → file_size_bytes for every WAV that exists on local SSD.
- On hit: promotes entry to MRU end, reads bytes from local SSD.
- On stale hit (file was deleted externally): evicts from index, continues.
- **Max size:** 2 GB (configurable via `FLOWTTS_DIST_CACHE__L1_MAX_BYTES`).
- LRU eviction: oldest digest is evicted first when the budget is exceeded.

**Result:** `l1_hit` — fastest possible path, no network, no disk seek for
entries that were recently served.

---

### Step 2 — Legacy flat-directory caches

**Files:** `flowtts/server.py` → `_VOICE_CACHE_MAP`, `flowtts/cache/cache_manager.py`

The pre-existing 22 GB+ per-voice caches (`cached_data_simran/`,
`cached_data_tara/`, etc.) use the old key format:

```
SHA256(raw_text_bytes)  →  <digest>.wav   (flat directory, no sharding)
```

CacheManager checks these directories using the legacy key so the existing
files are served without any migration.

- Voice → directory mapping comes from `_VOICE_CACHE_MAP` in `server.py`.
- Only checked for the voice that the request specified.
- On hit: warms the L1 index so the next request for the same text is served
  from the in-process LRU without even touching the filesystem again.

**Result:** `legacy_hit`

---

### Step 3 — L1 local SSD (sharded layout)

**File:** `flowtts/cache/storage.py` → `LocalStorageBackend`

New-format files generated by this server (or written back from GCS) live here:

```
~/FlowTTS/distributed_cache/
  ab/
    cd/
      abcdef...digest.wav
```

The two-level shard (`digest[:2] / digest[2:4]`) caps each leaf directory at
~65,000 entries regardless of total cache size, keeping filesystem performance
stable with millions of files.

- `exists()` → `Path.exists()` (single syscall)
- `read()` → `Path.read_bytes()`

**Result:** `l2_hit` (this is technically L1 disk, but the code labels local
sharded storage as "l2" to distinguish it from the in-process index).

---

### Step 4 — L2 Google Cloud Storage

**File:** `flowtts/cache/storage.py` → `GCSStorageBackend`

GCS is shared across **all** TTS servers. A file here means some server
generated this audio previously — even if this server has never seen it.

```
gs://kapturecx-ml/tts-cache/ab/cd/<digest>.wav
```

On a GCS hit:
1. Download WAV bytes.
2. Submit a background write-back to local SSD (`_executor.submit`).
3. Add to L1 in-process LRU index.
4. Increment hit counter in DragonflyDB (`HINCRBY audio:<digest> hits 1`).
5. Return bytes immediately.

The write-back means the next request for the same text on this server is
served from local SSD (Step 3) without touching GCS again.

**Result:** `l2_hit`

---

### Step 5 — Distributed lock (stampede prevention)

**File:** `flowtts/cache/distributed_lock.py`

At this point we have confirmed the audio is not in any cache layer.  Without
coordination, all 100 servers receiving the same uncached text simultaneously
would each start a GPU synthesis job.

**Lock acquire:**

```
SET lock:<digest> <random_uuid_token> NX EX 60
```

- `NX` — only set if the key does not exist (atomic)
- `EX 60` — auto-expire after 60 seconds (crash safety)
- `<random_uuid_token>` — proves ownership on release

**Three outcomes:**

| Result | Meaning | Action |
|--------|---------|--------|
| `ACQUIRED` | This server is first | Proceed to GPU synthesis |
| `WAIT` | Another server is generating | Wait, then re-check GCS |
| `DEGRADED` | DragonflyDB unreachable | Proceed optimistically (behaves like no lock) |

**Wait loop (WAIT path):**

```
while monotonic() < deadline:
    if GCS.exists(digest):   ← check every poll cycle
        return True           ← peer finished, serve from GCS
    if NOT Dragonfly.exists(lock_key):
        re-check GCS          ← lock expired/released
        return result
    sleep(min(backoff_ms, 500ms) ± 10ms jitter)
    backoff_ms *= 2
```

- Base poll interval: 50 ms, doubles each cycle, caps at 500 ms.
- ±10 ms jitter prevents 99 waiters all waking simultaneously.
- Timeout (default 30 s): if the peer never finishes, this server generates
  its own copy.

**Result on wait success:** `peer_hit` — 99 duplicate GPU jobs prevented.

**Result on miss (no lock configured, degraded, or timeout):** `miss` — caller
proceeds to GPU synthesis.

## Miss Path — GPU Synthesis

When `get()` returns `data=None`, `server.py` runs the full pipeline:

```
text
  │
  ▼  sglang LLM (FlowTtsSynthesizer)
audio tokens
  │
  ▼  ncodec decoder (TTSCodec.decode_async)
PCM float32 tensor
  │
  ▼  tensor_to_wav()
WAV bytes
```

For **streaming requests**, PCM chunks are collected in `_pcm_chunks` as they
arrive, concatenated at the end, then encoded as a single WAV for caching.

For **non-streaming requests**, the WAV is produced in one shot.

## Write Path — Non-Blocking Cache Store

**File:** `flowtts/cache/cache_manager.py` → `store_async()`

```
synthesis complete
        │
        ▼
WebSocket response sent  ◄── client gets audio NOW
        │
        │  (immediately after)
        ▼
store_async(key, wav_bytes)
        │
        ▼  ThreadPoolExecutor (background thread)
_write_sync(key, data)
        │
   ┌────┴──────────────────────────────────────┐
   │  L1 SSD: write to .tmp_ → os.replace()    │  atomic
   │  L1 index: LocalCache.put(digest, size)   │
   │                                           │
   │  L2 GCS: blob.upload_from_string(data)    │  PUT is atomic
   └───────────────────────────────────────────┘
        │
        ▼  (back on event loop via call_soon_threadsafe)
_on_write_done()
        │
   ┌────┴───────────────────────────────────────────┐
   │  Dragonfly: DEL lock:<digest>  (Lua, atomic)   │
   │  Dragonfly: HSET audio:<digest>                │
   │    path    = "gs://…/ab/cd/<digest>.wav"       │
   │    hits    = 0                                 │
   │    created_at = <unix epoch>                   │
   │    voice_id   = "simran"                       │
   │    model_version = "mira_hindi_v3"             │
   └────────────────────────────────────────────────┘
```

**Key property:** The client receives audio before any cache write begins.
Cache write latency (SSD fsync + GCS PUT) is completely off the critical path.

**Failure handling:**
- L1 write fails but L2 (GCS) is configured → log error, continue to GCS write.
- L2 (GCS) write fails → log error, L1 already has the data, retry on next miss.
- Process crashes after response but before write → entry is never cached; next
  request re-generates. Acceptable — TTS is cheap to re-generate.

## Failure Recovery Scenarios

### Scenario 1 — Generating server crashes mid-synthesis

1. DragonflyDB lock auto-expires after 60 seconds (`EX 60`).
2. The next waiter's poll loop sees `EXISTS lock:<digest>` → 0.
3. That waiter re-checks GCS → miss (nothing was written).
4. That waiter acquires the lock and generates.

No deadlock. Recovery time ≤ lock TTL (60 s by default).

---

### Scenario 2 — Generating server crashes after synthesis but before GCS upload

1. Lock auto-expires.
2. Next request is a cache miss everywhere.
3. A new server generates and uploads to GCS.

The audio is regenerated once. Acceptable.

---

### Scenario 3 — GCS upload fails (network blip)

1. L1 local SSD write succeeded.
2. GCS write is logged as an error but does not propagate.
3. This server serves the audio from L1 SSD on subsequent requests.
4. Other servers cannot find it in GCS → they generate their own copy on miss
   and upload it when their GCS connection recovers.

---

### Scenario 4 — DragonflyDB is down

1. `try_acquire()` catches the exception and returns `DEGRADED`.
2. All servers proceed to generate independently — exactly the pre-cache behaviour.
3. No extra latency. No errors surfaced to clients.
4. When DragonflyDB recovers, locks resume automatically on the next request.

---

### Scenario 5 — Partial file on local SSD

Local writes use `write(tmp) → os.replace(final)`.  `os.replace()` is atomic
at the OS level.  Readers never see a partially-written file.  If the process
crashes between `write(tmp)` and `os.replace(final)`, only the `.tmp_` file
is left on disk; the final blob path never appears.

---

### Scenario 6 — Stale L1 index entry (file deleted externally)

If a file is deleted from the SSD while its digest is still in the in-process
LRU:

1. `LocalCache.get(digest)` returns True.
2. `LocalStorageBackend.read(digest)` returns None (FileNotFoundError caught).
3. CacheManager evicts the digest from the L1 index.
4. Falls through to legacy / GCS / lock checks.

## Prometheus Metrics

All distributed cache events are recorded by `record_dcache_event()` in
`flowtts/monitoring/metrics.py`.

| Metric | Type | What it counts |
|--------|------|----------------|
| `dcache_l1_hits_total` | Counter | Served from in-process LRU |
| `dcache_l2_hits_total` | Counter | Served from local SSD or GCS |
| `dcache_legacy_hits_total` | Counter | Served from legacy flat-dir caches |
| `dcache_peer_hits_total` | Counter | Served after waiting for a peer lock |
| `dcache_misses_total` | Counter | Required GPU synthesis |
| `dcache_lock_waits_total` | Counter | Times a server waited for a peer |
| `dcache_duplicate_prevented_total` | Counter | GPU jobs avoided by lock |
| `dcache_write_errors_total` | Counter | Background write failures |
| `dcache_generation_seconds` | Histogram | GPU synthesis time on miss path |
| `dcache_write_seconds` | Histogram | Time to write to SSD + GCS |
| `dcache_lock_wait_seconds` | Histogram | Time spent waiting for peer lock |
| `dcache_l1_utilisation_pct` | Gauge | L1 SSD LRU fill % |
| `dcache_l1_entries` | Gauge | Number of files tracked in LRU |

Scrape endpoint: `GET /metrics` on the control API port (default 9090).

## Configuration

All settings live under `FLOWTTS_DIST_CACHE__` in `flowtts/core/config.py`.

```bash
# Master switch
FLOWTTS_DIST_CACHE__ENABLED=true

# L1 local SSD
FLOWTTS_DIST_CACHE__STORAGE_ROOT=/home/ubuntu/FlowTTS/distributed_cache
FLOWTTS_DIST_CACHE__L1_MAX_BYTES=2147483648          # 2 GB

# L2 Google Cloud Storage
FLOWTTS_DIST_CACHE__GCS_BUCKET=kapturecx-ml
FLOWTTS_DIST_CACHE__GCS_PREFIX=tts-cache
FLOWTTS_DIST_CACHE__GCS_PROJECT=your-gcp-project
FLOWTTS_DIST_CACHE__GCS_CREDENTIALS_FILE=/path/to/sa.json   # omit for ADC
FLOWTTS_DIST_CACHE__GCS_TIMEOUT_S=30

# DragonflyDB / Redis distributed locks
FLOWTTS_DIST_CACHE__REDIS_URL=redis://dragonfly.internal:6379/1
FLOWTTS_DIST_CACHE__LOCK_TTL_S=60
FLOWTTS_DIST_CACHE__WAIT_TIMEOUT_S=30

# Cache key scoping — change when TTS checkpoint changes
FLOWTTS_DIST_CACHE__MODEL_VERSION=mira_hindi_v3

# Background write thread pool
FLOWTTS_DIST_CACHE__WRITE_WORKERS=4
```
